# Open risks

Every known open risk, with its severity. Nothing is left out because it is awkward. Updated 5 November 2026 (Milestone 17). Evidence: `docs/HARDENING.md`.

**Severity:** Critical blocks the pilot. High must be fixed or explicitly accepted before real schools. Medium is fixed during the pilot. Low is tracked.

## Critical

| #   | Risk                                                      | Why it matters                                                                                                                                             | What closes it                                                                                                    | Who                     |
| --- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------- |
| C1  | No independent security test                              | The guide requires one before real schools join; nobody outside has tried to break it                                                                      | Commission a tester; scope in HARDENING.md; fix what they find                                                    | Owner                   |
| C2  | No legal review of consent, contracts and breach handling | DPDP duties start 13 May 2027; consent wording, school contracts (data processing), the 6-hour and 72-hour clocks and children's data rules are unreviewed | Lawyer reviews consent notices, terms, the data processing agreement and the incident workflow                    | Owner                   |
| C3  | No OTP provider for live                                  | With simulation off (the live default), live refuses OTP sign-in, so parents and staff can't sign in                                                       | SMS or WhatsApp provider account with DLT-registered templates; then an adapter (small code change)               | Owner, then Claude Code |
| C4  | No message providers for live (push, WhatsApp, SMS)       | With simulation off, absence alerts and notices fail visibly as "no provider"; with it on, nothing reaches parents' phones                                 | FCM project, a WhatsApp business provider and an SMS provider; then adapters and an allowlisted rehearsal in test | Owner, then Claude Code |
| C6  | Simulation can be switched on in live                     | With `simulate_providers = "on"`, sign-in codes are shown on screen to whoever asks: anyone who knows a phone number can sign in as that person            | Keep it off in live (the default); use it only before any real school is on live, and turn it off once C3 closes  | Owner                   |
| C5  | Nothing has run in AWS                                    | The test deploy, migrations on RDS, smoke tests and the timed restore exist only as code checked locally                                                   | Follow `infra/README.md`: accounts, apply test, secrets, first deploy, first restore check                        | Owner                   |
