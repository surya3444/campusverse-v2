# 0003 Platform services choices

Date: 2026-11-04 · Status: accepted

| Topic                 | Decision                                                                                                                                                                      | Why                                                                                                                                                                                  |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Local S3              | `adobe/s3mock:5.2.3` in Docker Compose and CI                                                                                                                                 | MinIO's community image is no longer published. s3mock is maintained and speaks the S3 API we use. It doesn't check signatures, so signed-URL limits are only really enforced on AWS |
| Event names           | Always `domain.entity.verb.v1`. The guide's `consent.changed.v1` becomes `platform.consent.changed.v1`                                                                        | One rule, checked by the outbox                                                                                                                                                      |
| Cross-tenant plumbing | Schema `ops`: outbox, processed events, provider references, public document verification. Allowlisted by the RLS suite                                                       | Workers and webhooks start before a tenant is known. Only ids, codes and hashes are kept here                                                                                        |
| Outbox writes         | RLS on `ops.outbox`: inserts only for the current tenant; the relay reads all                                                                                                 | Tenant code can't emit for another tenant                                                                                                                                            |
| Exactly-once          | `handle` runs once per consumer per event, recorded in `ops.processed_event` in the same transaction. External work (`afterCommit`) is repeat-safe and claims rows atomically | A duplicate event changes nothing; a crash mid-send finishes on retry                                                                                                                |
| Integration tests     | Run one file at a time                                                                                                                                                        | They share one database and the global outbox relay                                                                                                                                  |
| PDF text              | Latin only (pdf-lib standard fonts). Other scripts are refused                                                                                                                | Regional Noto fonts come with Certificates in Milestone 12                                                                                                                           |
| Providers             | Development prints masked lines. Test and production send nothing until real FCM and MSG91 adapters exist, so deliveries fail visibly as `no_provider`                        | No fake success outside development                                                                                                                                                  |
| Malware scan          | `devScanner` (EICAR only) refuses to start in production                                                                                                                      | A real engine (ClamAV or a managed scanner) arrives with infrastructure in Milestone 16                                                                                              |

## Known limits, deliberately deferred

- A delivery stuck in `sending` (worker died between claim and send) needs a sweeper job. Add it with monitoring in Milestone 16.
- A provider send can repeat if the worker dies after sending but before recording `sent`. It's at-least-once at the provider edge. Pass our delivery id as the provider's client reference where the provider supports it.
- Per-tenant fairness across queues uses plain BullMQ queues. Add per-tenant rate limits or groups once one school's bulk job is seen to delay another.
- Bulk sends with approval, recall and per-language previews belong to the Notices screen (Communications UI).
