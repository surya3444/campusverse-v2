# 0005 API and school setup choices

Date: 2026-11-04 · Status: accepted

| Topic                | Decision                                                                                                                                                            | Why                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| apps/api             | NestJS 12 on Fastify 5, built in Milestone 7 (no earlier milestone created it)                                                                                      | Setup is the first work a screen has to call                                      |
| Dependency injection | Explicit `@Inject(TOKEN)` everywhere; no `emitDecoratorMetadata`                                                                                                    | Runs the same under tsx/esbuild and tsc                                           |
| Auth on requests     | Bearer access token plus `x-org-id` and `x-person-id`, accepted only if the login is linked to that person                                                          | The client chooses a profile; the server never trusts the choice by itself        |
| Error shape          | `{ code, message, field?, details?, requestId, retryable }`, one filter for everything                                                                              | Build Guide API rules. Request bodies are never logged                            |
| Contracts            | `packages/contracts` (Zod), shared by API, web and mobile                                                                                                           | One source of truth for inputs                                                    |
| Long work            | Import commit and invites run in the worker; the API returns 202 and the client polls                                                                               | Build Guide: long tasks never run in API requests                                 |
| Signup               | `provisionSchool`, called by a development CLI (`pnpm --filter @campusverse/api provision`) until the admin portal (Milestone 14)                                   | Public self-signup needs verification and anti-abuse design first                 |
| OTP delivery         | Development prints the code in the API log; elsewhere OTP sign-in is refused until an SMS/WhatsApp provider is configured                                           | No fake success outside development                                               |
| Excel                | `read-excel-file` to read, `write-excel-file` for templates and test data, `fflate` to size-check zips before parsing                                               | Small, maintained libraries; SheetJS on npm is outdated                           |
| Undo                 | `import_batch_id` on created rows plus a RESTRICTIVE delete policy: the app can delete imported rows and nothing else; foreign keys refuse undo once data is in use | Reversible imports without giving the app general delete rights                   |
| Rule data            | `packages/rules`: year templates for CBSE and the four states, CBSE classes and default subjects, each with a source and `verified: false`                          | Spec: state rules as data, checked against official orders before relying on them |
| Wizard screens       | Deferred                                                                                                                                                            | They depend on the design changes still to be discussed                           |
