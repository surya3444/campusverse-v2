# 0008 People records

Date: 2026-11-04 · Status: accepted

| Topic                        | Decision                                                                                                                                                                                                      | Why                                                                                      |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| One person across places     | `institution_membership` (student or staff, with a date range and an exclusion constraint) links a person to each institution. The person row is never duplicated                                             | A school student who joins the group's college keeps one record                          |
| Placement                    | people/records defines `AcademicPlacementPort`; school/enrolment implements it (`schoolPlacement`). Shared tables have no foreign key to an academic table                                                    | Shared modules stay separate from school, college and university academics               |
| Writes between modules       | Other modules write people, memberships, roles and enrolments only through those modules' contracts (`createPerson`, `assignRole`, `enrol`, …), in the caller's transaction                                   | One owner per table; dependency-cruiser enforces the imports                             |
| Effects on other modules     | Staff exit emits `people.staff.exited.v1`; school/setup ends allocations in a consumer                                                                                                                        | People never reaches into academic tables                                                |
| Sensitive identifiers        | Aadhaar and PAN are sealed with AES-256-GCM (`packages/crypto`): versioned keys from `FIELD_KEYS`, with kind, organisation and person as authenticated context. Only the last four digits are stored in clear | A database dump or a log line never holds a full number                                  |
| Reveals                      | A full reveal needs a permission and a reason, is audited as restricted, and the screen hides the value after 30 seconds                                                                                      | The spec's restricted-data rule                                                          |
| Backfills                    | `cv_migrator` has BYPASSRLS (roles.local.sql). The app's role, `cv_app`, still doesn't                                                                                                                        | Migrations that copy tenant rows must see every tenant; FORCE RLS applies to owners too  |
| New permissions              | Add them to the role templates (`SCHOOL_ROLES`) **and** grant them to existing schools in a migration, which bumps `permission_version`                                                                       | New schools and existing schools must agree; cached snapshots must go stale              |
| Ending roles and memberships | The end is `greatest(start, last day + 1)`, so a range starting after the last day becomes empty; empty ranges are hidden                                                                                     | A role starting tomorrow must not survive an exit that ends today                        |
| Cross-module tests           | Tests that need a real school live in school/setup (`people-records.db.test.ts`)                                                                                                                              | A shared module must not depend on a school module, even for tests (turbo found a cycle) |

**Known gaps:** no staff list or record screens yet (the API exists). Name correction, APAAR, documents and section change have API endpoints but no edit forms. School/setup's readiness, overview and invite reports still read other modules' tables directly.
