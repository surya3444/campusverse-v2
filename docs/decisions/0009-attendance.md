# 0009 Attendance and offline sync

Date: 2026-11-04 · Status: accepted

| Topic              | Decision                                                                                                                                                                                                                                          | Why                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Mobile             | Teacher attendance ships on the web now, with an offline queue in IndexedDB. The Expo app (SQLite queue, same sync API) arrives with the parent app in Milestone 10                                                                               | Agreed with the owner: the server protocol is the hard part, and it is shared |
| Sync protocol      | `POST /api/v1/sync/events` takes up to 50 queued events. Each has a device-made UUIDv7 `eventId`, which is its idempotency key: stored as the primary key of `school_attendance_event`, so a resend, or two at once, is accepted once             | The guide's exit check: offline marks sync once after reconnecting            |
| Answers            | accepted, duplicate, conflict or rejected (with a code) are final, and the device drops the event; only a network failure or 5xx keeps it queued                                                                                                  | A bad event can't block the queue forever                                     |
| Who marked         | The session decides; an event whose `actorId` differs is rejected (`other_actor`)                                                                                                                                                                 | Client input never chooses the actor                                          |
| What is stored     | Events are append-only; `school_attendance_day` is the read model. Corrections, conflict resolutions, leave approvals and holidays each add an event                                                                                              | The school can prove what happened and who changed it                         |
| Second submission  | Differences become `school_attendance_conflict` rows for a coordinator; the first submission stands                                                                                                                                               | Two teachers or two devices never overwrite each other silently               |
| Absence alerts     | After the school's delay, from a scheduled worker task that re-checks the day; `absence_alerted_at` and the message dedupe key make it once per student-day                                                                                       | Late arrivals can be fixed before parents are told; retries never double-send |
| Percentages        | Integer basis points, half days count half, holidays are not working days, rounded down                                                                                                                                                           | No floats; never show a pass that isn't there                                 |
| Thresholds         | `attendanceRule(board)` in packages/rules (CBSE 75%, unverified source); the 80% warning level is a product default                                                                                                                               | Rule data stays out of module code                                            |
| Sign-out           | The web blocks sign-out while submissions are queued                                                                                                                                                                                              | The spec: unsynced marks on a lost phone are lost                             |
| Cross-module reads | Sections and class teachers via `@campusverse/school-setup` (`sectionInfo`, `sectionsOn`, `classTeacherSections`); rosters via `@campusverse/school-enrolment` (`sectionRoster`, `sectionOf`); delivery proof via communications' `messageStates` | Module boundaries                                                             |

**Known gaps:** no service worker yet, so the marking page must be open before the connection drops (it survives losing the network, not a reload while offline). Names still come from `person` joins, as in earlier modules.
