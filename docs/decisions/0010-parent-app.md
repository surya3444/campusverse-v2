# 0010 Parent app, notices and the Expo app

Date: 2026-11-04 · Status: accepted

| Topic                       | Decision                                                                                                                                                                                    | Why                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Spec                        | `docs/specs/PARENT_APP.md`, drafted from the Schools Release spec and agreed with the owner before building; open questions carry defaults                                                  | The guide says not to start a milestone without its spec             |
| App                         | One Expo app (`apps/mobile`, SDK 58, expo-router) for parents and teachers, by role. Verified through its web build in Playwright and unit tests; the owner runs it on a phone with Expo Go | Agreed with the owner; no simulators here                            |
| How the app reaches the API | Directly, as a device: Bearer token plus the chosen profile, as the API was designed. The web app's cookie pass-through is for browsers only                                                | Phones can hold tokens safely in the secure store                    |
| Token storage               | expo-secure-store on phones. The web build keeps the session in sessionStorage and is for tests only, served same-origin by `scripts/serve-web.mjs` (no CORS opened on the API)             | No tokens in plain phone storage; no new browser product by accident |
| Offline queue               | SQLite on phones, same sync protocol as the web (decision 0009)                                                                                                                             | One server rule: each event id accepted once                         |
| Config                      | `EXPO_PUBLIC_API_URL` is the app's only build-time setting, read in `lib/config.ts` (one lint exception)                                                                                    | Expo inlines it at build time                                        |
| Notices                     | compose → approve → preview → send with a 2-minute undo window → worker releases → per-guardian, per-channel tracking. Urgent from principal or administrator goes at once without approval | The spec's message types and bulk-send rule                          |
| Audience                    | `AudiencePort` in communications; school/setup implements `schoolAudience`                                                                                                                  | Communications is shared and knows nothing about classes             |
| One message per guardian    | A parent of several children in the audience gets one notice, filed under a child only when exactly one is in it                                                                            | No floods; the spec's "limits" rule                                  |
| Read and acknowledged       | Opening in the app is a read on the push channel; acknowledged is a message state above read, recorded once. States never move back                                                         | "Delivery status is correct for every channel"                       |
| Languages                   | English required on every notice; guardians choose their language in the app; app text drafted in Kannada, Telugu, Tamil, Hindi and Urdu, marked for native review; Urdu sets right to left | Spec: per-language versions, user language first                     |
| Tests and the dev worker    | Integration tests share the development database, so a running `pnpm dev` worker can take their outbox events; stop it before `pnpm test:integration`                                       | Found as a flaky notices test                                        |

**Known gaps:** see `apps/mobile/README.md` (push on device, store builds, Maestro, fonts, native RTL restart) and the spec's "Out of scope" list.
