# 0011 Fees and online payment

Date: 2026-11-05 · Status: accepted

| Topic                  | Decision                                                                                                                                                                                                                                  | Why                                                                         |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Where fees live        | `modules/shared/finance` (shared, as the guide lists). Which students a plan covers comes through the communications `AudiencePort` (school: `schoolAudience`)                                                                            | Finance never reads academic tables                                         |
| Money                  | bigint paise in the database, safe integers in code, splits by the largest remainder, percentages in basis points, rounding down where the school would otherwise over-give. Property tests with fast-check                               | "Money is integer paise. Never float."                                      |
| Receipt numbers        | Per legal entity and financial year, from a counter row locked inside the payment's transaction: no gaps, no duplicates                                                                                                                   | Statutory numbering                                                         |
| Receipts immutable     | No UPDATE/DELETE grant and an append-only trigger; reversals are credit notes, refunds are vouchers, each with the next number                                                                                                            | The spec: never edited                                                      |
| Counter idempotency    | `Idempotency-Key` header required on `POST /finance/payments`, stored unique per org; the web pass-through forwards it                                                                                                                    | The guide: writes for money need an Idempotency-Key                         |
| Online payment         | Razorpay Payment Links (hosted page, opened from the app or a message) rather than a native checkout SDK                                                                                                                                  | Works in Expo Go and from a WhatsApp link; no app store build needed to pay |
| Webhooks               | Verified over the raw body (Nest `rawBody`), event ids recorded in `ops.webhook_event`, applied under a row lock on the payment, with a unique receipt per payment as the last guard; a lost webhook is caught by scheduled status checks | Exit check: repeated webhooks create one receipt                            |
| Amount mismatch        | The payment becomes `unmatched` and appears in reconciliation; no receipt is guessed                                                                                                                                                      | Paid-but-wrong-amount needs a person                                        |
| Maker-checker          | Concessions, refunds and reversals: requester and approver must differ, enforced in code and by CHECK constraints                                                                                                                         | Spec "Separation"                                                           |
| Gateway in development | A fake gateway signs its own webhooks with the same HMAC; a development-only endpoint completes a payment                                                                                                                                 | Test the real verification path without a Razorpay account                  |
| Config                 | `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET` all or none; live keys refused outside the live environment; `PAYMENT_RETURN_URL` optional                                                                            | No half-configured payments                                                 |
| Plan versions          | A published plan is fixed; a change is a new version in the same family; issued invoices change only by explicit adjustment or concession                                                                                                 | Spec "Fee changed mid-year"                                                 |

**Before real money:** a Razorpay account (test keys first), the webhook URL registered with the secret, a CA's review of head tax classes, and the school's own receipt-number format if it differs.
