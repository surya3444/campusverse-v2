# 0015 Verse AI

Date: 2026-11-05 · Status: accepted

| Topic             | Decision                                                                                                                                                                                                                  | Why                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Spec              | `docs/specs/VERSE_AI.md`, drafted from the guide and the release spec; open questions carry defaults                                                                                                                      | The guide: no milestone without its spec                             |
| Layout            | `packages/verse-ai` is the mechanism (tools, gateway, models, cleaning); `modules/platform/verse` owns asking, logging, budget and switch; each module defines its tools; the API composes them (`apps/api/src/verse.ts`) | Guide layout; a module owns its tables and its data                  |
| Model             | Claude through the Anthropic API, `claude-opus-5-5`, low effort, prompt caching, server-side refusal fallbacks (`fallbacks: 'default'`). SDK `@anthropic-ai/sdk` 1.3 (old enough for the release-age rule)                | Default model; short operational answers                             |
| No key            | Development uses an offline keyword model; elsewhere Verse AI is off                                                                                                                                                      | Works and tests without sending anything                             |
| Permissions       | Two layers: the gateway offers only tools whose permission the person holds; each tool calls its module's use case, which checks `can()` under RLS. Tools that weren't offered are refused even if the model asks         | Exit check: nothing outside the person's permissions                 |
| Data              | Only `public` and `operational` tools until model hosting and terms are reviewed; tool output scrubbed of phones, emails and 12-digit identifiers and fenced as data                                                      | Guide: no student data to a model without review; injection safety   |
| Writes            | None. The notice draft tool returns a link to the normal notice screen, pre-filled                                                                                                                                        | Stage B is drafts only                                               |
| Budget and switch | `verse_ai` flag per customer (off by default; on for development schools); monthly tokens per plan (`control.plan.ai_monthly_tokens`: Pilot 2M, Standard 10M)                                                             | Guide: budgets and an off switch; the product works without Verse AI |
| Logs              | `verse_request` append-only: question, tools with outcomes and data classes, answer, tokens, outcome; audit row with ids only                                                                                             | Guide: prompt, tools, data classes and result are logged             |
| Evaluations       | Always: the exit check with offline and deliberately misbehaving scripted models. Live: the same questions against Claude, only with a key and `VERSE_LIVE_EVAL=1` (costs money)                                          | Evaluate permissions, isolation, injection, language, refusal        |

**Known gaps:** see `modules/platform/verse/README.md`.
