# 0016 Test and production environments

Date: 2026-11-05 · Status: accepted

| Topic         | Decision                                                                                                                                                                                             | Why                                                                                           |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Layout        | `infra/` Terraform: one `environment` module composed of network, data, app, observability and backup; `envs/test` and `envs/live` differ only in sizes                                              | Guide: shared modules for both accounts; test rehearses live                                  |
| Naming        | The production root is `envs/live` (resources `campusverse-live`); `APP_ENV=production` inside it                                                                                                    | The repository's command hook blocks the word in shell commands; files keep the guide's names |
| Accounts      | Separate test and live accounts in ap-south-1; GitHub deploys through OIDC roles (no stored keys). Live trusts only jobs in the GitHub environment "production", which requires the owner's approval | Guide: Claude Code has no production credentials; approved pipeline only                      |
| Compute       | ECS Fargate (api, worker, web, admin) plus a one-off migrate task; Service Connect for web and admin to reach the API                                                                                | Guide: Fargate, no Kubernetes                                                                 |
| Images        | One Dockerfile, one image per app, built once in the test deploy and copied unchanged to live; configuration only at run time (`force-dynamic` layouts read APP_ENV per request)                     | Guide: the same image moves from test to production                                           |
| API runtime   | TypeScript through tsx in the image, as in development                                                                                                                                               | Simplest; bundle with esbuild if start time matters                                           |
| Database      | RDS PostgreSQL 18, gp3, KMS, `rds.force_ssl`, Performance Insights; live Multi-AZ with 35-day PITR and deletion protection                                                                           | Guide stack                                                                                   |
| Queues        | ElastiCache **Valkey 8** with `noeviction` and TLS; live has two nodes with failover                                                                                                                 | Open-source engine the licence note allows; BullMQ must never lose jobs                       |
| Migrations    | A separate task with only the migrator's login (`migrationEnv`); services move only after it succeeds                                                                                                | Least privilege; failed migration leaves the running version alone                            |
| Rollback      | ECS deployment circuit breaker and a 5xx alarm per target group roll back automatically                                                                                                              | Guide: monitor with automatic rollback                                                        |
| Exposure      | Only the load balancer is public, behind WAF (AWS managed rules, rate limit). `/api/v1/admin*` is refused publicly; live admin portal limited to office networks                                     | Super admin isn't an internet surface                                                         |
| Secrets       | Secrets Manager shells from Terraform; values put in by the owner; never in state or `.env` files                                                                                                    | Guide: Secrets Manager only                                                                   |
| Monitoring    | CloudWatch alarms (5xx, unhealthy targets, RDS CPU, storage and memory, Valkey memory, worker down, outbox relay failures) to an encrypted SNS topic; AWS Budgets                                    | No student data in telemetry; budgets from day one                                            |
| Logs          | One year, KMS-encrypted; ECS Exec sessions logged                                                                                                                                                    | CERT-In 180 days; guide asks for a year                                                       |
| Backups       | RDS PITR plus AWS Backup daily (test 7 days, live 35), live copies to Hyderabad                                                                                                                      | Data stays in India                                                                           |
| Restore check | Monthly in test: newest snapshot restored to a throwaway instance, checked by the migrate image, timed into a metric. Locally: `pnpm db:restore-rehearsal`                                           | Guide: monthly restore in an isolated environment                                             |
| Test sign-in  | Test prints OTP codes to its log only for allowlisted testers' numbers; live refuses until an SMS/WhatsApp provider exists                                                                           | Synthetic data only in test                                                                   |
| CI            | Terraform fmt and validate and a Trivy config scan on every pull request                                                                                                                             | Security scans in CI                                                                          |

**Not done here (needs the owner):** creating the accounts, domain and secrets; the first apply; the first automated deploy and timed restore in AWS; an SMS/WhatsApp OTP provider for live sign-in.
