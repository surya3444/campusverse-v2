# 0020 Institution depth: fields, roles, stamps, staff attendance, AI providers

Date: 2026-11-06 · Status: accepted · Spec: docs/specs/INSTITUTION_DEPTH.md

| Topic            | Decision                                                                                                                                                                                                                | Why                                                                                 |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Custom fields    | Definitions in `custom_field` per entity; values in `custom_field_value` (org, entity, record id, field id, typed JSON value). The owning module validates through `platform/fields`; values never replace core columns | Owners extend every section without migrations; core data stays typed and queryable |
| Roles            | Roles stay per organisation (`role`, `role_grant`). Owners create and edit roles; a sensitive permission waits in `role_grant_request` until a different owner approves. Assignments carry scope and dates as today     | Owner's choice: custom roles with approval                                          |
| Owner            | New organisation-scope role `owner`; the onboarding admin gets it. Only owners manage roles, fields and approvals                                                                                                       | Someone must hold the keys, and it must be visible                                  |
| Who did this     | Read from `audit_event` (ids only) and resolved to names at read time; every record screen shows created and last changed, and a History panel                                                                          | Audit rows stay free of personal data; screens still name people                    |
| Files            | Reuse `stored_file` (scan, signed links). Photos are `purpose = 'photo'`; logos `logo`. Documents link to records through `record_document` with folder, version and status                                             | One storage path, already scanned and audited                                       |
| Staff attendance | Check-ins from people (web or app) plus an office register; the register wins and every correction needs a reason                                                                                                       | Owner's choice: both                                                                |
| AI providers     | `packages/verse-ai` gets a provider interface; Claude (decision 0015) and OpenAI adapters; `VERSE_PROVIDER` picks. Same tools, permissions, budgets and logs                                                            | Owner's choice: both, switchable; supersedes only the model row of 0015             |
