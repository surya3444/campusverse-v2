3.6 How CampX's systems work together, and what Medha adds
CampX describes a shared core that every service inherits, with context-aware access.
The Security page says each request is tied to institution, user , role and data domain
before business logic runs. It names the core's topics on its Blueprint page but publishes
<<PAGE 15>>
no detail. The visible hand-offs are:
Enrollment → Academics and Finance at onboarding.
Attendance and leave → P ayroll.
Fees and attendance → exam eligibility .
Fees and payroll → GL and T ally .
Academics → placements eligibility .
Events and feedback → accreditation evidence.
Medha is a permission-aware conversational layer over all five systems, in four modes:
Mode For What it does
Learning Assistant Students Answers course questions and shares reference
material
T eaching Assistant Smart Analysis W orkflow Agents F aculty Administration Administration Helps with course and assessment work
One click on any table returns averages, outliers
and next steps
Drafts a task (for example a feedback form), routes
it for review and publishes it under the user's

It also answers questions that span systems ("at-risk students with pending fees"), and
accepts voice from students. It runs under three governance rules: it sees only what the
user sees, logs every step on the shared audit trail, and runs inside the platform. The site
does not state languages, the model used (except bring-your-own on Enterprise) or agent
types beyond the feedback-form example.
